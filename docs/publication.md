# Context Layer 公开发布约定

本项目计划公开内部存储规范、MCP 交付规范和参考实现，使其他录音分析服务与上下文消费者能够独立接入。目前两份 0.1 规范均为草案；现有 Recording MCP 是早期原型，完整兼容实现尚待完成。

## 公开范围

发布材料包含规范、代码、测试和合成示例。运行时数据库、真实录音、转写、身份映射、音频地址与客户端凭据属于使用者的数据，不随项目材料分发。当前 `.gitignore` 排除了 `data/`、数据库文件和 `bin/`；准备发布包时同样只包含明确列出的项目材料，不能直接打包整个工作目录。

示例使用虚构身份、通用项目与占位路径。合成示例不能直接摘用个人历史沟通，再仅通过“合成”标签作为公开材料。跨文件引用必须一致，示例改变后重新校验 JSON、来源引用、字节预算和相关测试。

Event 和 Entity 的 `classification=public` 是数据分类元信息，不是公开发布授权，也不会自动上传数据或改变访问权限。

## 契约版本

`internal-context/0.1` 表示存储语义版本；MCP 成功响应的 `contract_version=0.1` 表示本项目交付契约版本。它们与 MCP 官方协议版本分别管理。`schema_version` 标识注册事件类型的负载版本，`projection_version` 标识状态推导规则；客户端不能以工具同名推定版本兼容。

0.1 正式发布前允许评审修订，修改必须同步两份契约、示例和验收场景。发布时为规范与参考实现分别记录版本及兼容状态，不以原型存在宣称规范已经实现。

正式发布后的快照保持不变。改变已有字段含义、必填要求、排序、去重、时间、有效性或错误行为，需要发布新的领域契约版本；在 0.x 阶段可以使用 0.2 等后续版本表达这种变化。仅修正文档错字、不改变契约时，可以发布勘误并注明修订。

新事件类型先登记名称、负载版本、引用和投影语义。数据库升级应保留不可变历史与原始版本，通过明确迁移或新投影重建完成，不能让软件升级悄悄改写旧事件。
